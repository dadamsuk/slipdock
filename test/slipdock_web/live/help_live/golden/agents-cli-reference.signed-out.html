Start here

guide [section]
how to use these boards as a work tracker, from the server itself: epics and subcards, what to pick up next, what to write back as you go. With no section, the short guide, ending with the names of the rest; `guide <name>` one of them (`guide wiki`); `guide all` the whole guide, which is long (GET /api/guide?section=short|<name>|all)

Find anything

(semantic: matched by meaning, so the words you type needn't be the words that were written; covers cards, comments and status updates)

search <words...>
search every board you can see
--board B     only that board and its sub-boards
--kind cards|pages|files|all   cards and comments, wiki pages, wiki files, or all (default)
--limit N     how many results (default 20, max 50)
--archived    include archived cards (a card's #id or link
              as the query finds it, archived or not)
--full        print the whole matching text, not a snippet
ask <question...>
ask the assistant, which searches for itself and answers in prose, naming the cards it read
--board B     keep it to one board (id, code or name)
search-status
what is indexed, and whether anything is queued
saved [--ask | --mode search]
the searches and questions you have saved (yours alone)
save <words...> [--ask]
save a search (with --ask, a question)
unsave <words...> [--ask]
take one off the list (or `unsave --id N`)

Auth

url [<url>]
which server to talk to, saved in ~/.config/slipdock/url so it need not be in the environment (`url --remove` forgets it). $SLIPDOCK_URL still wins for a one-off
auth
sign in without a token: shows a code to approve in a browser, then saves the token it is given
--label TEXT  what the approval screen calls this client (default: this host)
--scope read|write   what to ask for (default: write)
auth <token>
save an API token directly (create one at /account/tokens)
names [full|short]
says or sets Names in trees and lists: full titles or short names, in the web app and clients
whoami
show who you are signed in as (and how many things are waiting on you)
work [--board B] [--done]
my work: what is waiting on you (waits, review and waiting flags, runner trouble, cards in progress with nobody on them), oldest first, then my cards by due date
work --dismiss <card> | --undismiss <card> | --dismissed
take an item off my own list, held on its cause (a second failed job or a new wait shows again); undo it; list what I dismissed
work --mute <board> | --unmute <board>
keep a board's tree off my own list; the board works as before for everyone
multiboard [--list L]... [--limit N] [--by board|list|grid]
the top N cards (default 5) of lists from several boards; L is a list id or board/list ("ops/To Do"). No --list: the view saved on the Multiboard page
multiboard <saved>
one of your saved multiboards (id or name), with its cards
multiboards
your saved multiboards: id, name, colour, lists
save-multiboard <name> [--list L]... [--limit N] [--by B] [--color C]
save a multiboard view by name; it goes on your home page among your boards. No --list: the page's view
set-multiboard <saved> [--name N] [--color C] [--list L]... [--limit N] [--by B]
rename, recolour or change a saved multiboard
delete-multiboard <saved>
delete a saved multiboard (the boards stay as they are)
passkeys
your passkeys: name, when added, when last used
passkeys remove <id>
remove one (a lost phone) — it can't sign in after. Adding one needs the device, so is in a browser only
inbound log
your last 50 emails to this server's inbound addresses, and what came of each: what it made, or why it bounced or was ignored. Only while the server receives mail
inbound <board> [--rotate]
your address for emailing cards onto a board (it only takes mail from you, and the board's permitted senders, which it lists); --rotate makes a new one, and mail to the old one bounces from then on
--folder F                        a wiki folder's own address instead (a path, name or
                                  id): mail to it is a page in that folder
inbound me [--rotate]
your personal Quick Add address: the subject picks the board, list, priority and due date
--ack on|off                      email me back a link to each card my mail makes
ai-key [<key>]
show your stored API key (masked), or set one; `ai-key --remove` deletes it
ai
which model your AI requests go to: endpoint, key, model
ai-endpoint [<url>]
point at any OpenAI-compatible API — a local LM Studio, Ollama, llama.cpp, vLLM — instead of OpenRouter; no key needed for most. `--key K` sets one at the same time, `--remove` goes back to the server's default
ai-models
what that endpoint can run
ai-model <id>
pick one (`--embed <id>` for the search index too). AI features need a key or an endpoint
logout
forget the saved token

Wiki

(Markdown pages on a board: how it works, what was decided and why. A page answers to its code — W-31 — its slug, or board/slug.)

page ls <board> [--q TEXT] [--archived|--all] [--template] [--draft] [--folder F | --no-folder] [--recent] 
--recent: the most recently edited first, the
newest 100 (the wiki tree's Recent view)
page tree <board>
the page tree, nesting shown by indent
page read <page>
print the Markdown source
page tags <board>
the tags its notes give themselves (front matter tags and inline #tags), with counts. page ls <board> --note-tag T lists the notes tagged T or anything under it (T/sub)
page props <page> [--body TEXT | --file F | --clear] [--message M]
the front matter its file came with, kept exactly as written; with --body/--file, replace it (YAML only, no --- lines); --message M is why, recorded in the page's history
page render <page> [--format markdown|html|text]
the same with every reference resolved: links followed, #412 filled in with what the card says now, [[!toc]] expanded
note <text...>
save a quick note in your wiki; the server names and files it, and says where (--body - reads stdin)
page new <board> <title...>
write a page
--body TEXT | --file F | --body -   (- reads the body from stdin)
--parent P    put it under another page
--folder F    file it in a folder — a name or a path, made if it is new
--card N      a page for that card: in its folder, pinned to it
--summary S   one line, shown in listings
--message M   why, recorded in the page's history
--draft       only writers can see it
page edit <page> [--title T] [--summary S] [--body TEXT|--file F|--body -] 
--message M   why (write one every time)
--base-hash H the hash you read (see `page read --json`); a save that
              would land on someone else's is refused, not applied
--draft | --publish
the card facets, so a doc on the board reads like one:
--priority P  --flag F (repeatable) / --flag F --off
--tag T (repeatable) / --tag T --off   the board's tags, by name
--set-tag T (repeatable) replaces them all  --no-tags clears them
                            (not the note's own #tags: those are its text)
--start DATE | --no-start   --due DATE | --no-due
--percent N | --no-percent  --color C | --no-color
--assignee EMAIL | --no-assignee   --done | --undone
--folder F | --no-folder
--icon I | --no-icon        what it wears in the wiki, tinted by --color
                            (icons: see `folder new`)
page file <page> --folder F | --no-folder
file it in a folder, or take it out of one. Where a page is *kept*; `page mv` is what it is *part of*
page file <page> --also F | --not-in F [--board B]
file it in one more folder as well as its home (one page, several places), or take it out of one. F is a folder on its board, on --board B, or a path in your wiki ("/Projects/Notes")
page mv <page> [--parent P | --root] [--position N|top|bottom]
page mv <page> --board B [--folder F] [--dry-run]
to another board of yours: it keeps its code, history and comments; tags, fields and pins go where that board has a match (--dry-run says which won't)
page rm <page> [--purge]
archive it (--purge deletes, owner only)
page restore <page>
page history <page> [--limit N]
every save, who made it and why
page diff <page> [--rev N] [--against M]
what a version changed (default: the latest), or with --against how it differs from version M
page revert <page> --rev N [--message M]
page ai <page> <tool>
an AI tool over the page, on your AI key: summarise, key_points, actions, titles or improve. It only answers
page sections <page>
the heading paths a section may be addressed by
page section <page> <path>
print one section
page section <page> <path> --append TEXT | --body TEXT | --file F [--message M]
add to, or replace, one section. Appending cannot conflict and needs no hash — the write to prefer.
--append - and --body - read the text from stdin
page append <page> --body TEXT|--file F [--message M]
add to the end of the page
page encrypt <page> [--section S] [--hint H] [--purge-history]
encrypt the page, or one section, in Meld Encrypt's format (Obsidian opens it). Done here: the passphrase, asked for twice, and the text never reach the server. Earlier revisions still holding the text are counted;
--purge-history deletes them (the board's owner only)
page decrypt <page> [--section S] [--in-place]
print the page, or a section, with its encrypted blocks opened; --in-place removes the encryption and saves the plain text. Both take --passphrase-file F or $SLIPDOCK_MELD_PASSPHRASE where nobody can type it
page links <page>
what it points at, what points at it, what it wanted
page pin <page> --card N | --page P [--off]
"this page is *the* spec for that"
page wanted <board>
pages linked to but never written — the wiki's backlog
page resolve <board> <title...>

page query-help

page query <board> --body -
try a block without writing it anywhere
page place <page> <column> [--before REF]
put the page in one of its board's lists, so it sits beside the work and can be dragged like a card (REF: a card's number, or page-7)
page unplace <page>
take it off the board; it stays in the wiki
page publish <page> [--off]
read-only at a public link; its live queries are answered once, when you publish (publish again to refresh them). --off withdraws the link
page share <page> [EMAIL|GROUP] [--read|--comment|--write] [--off]
share it with a person (an email; a stranger is invited) or a group of yours, read only (default),
--comment (read, comment, report a status, vote;

shared
what other people have shared with you, by owner; `page read` and `page edit` take the codes it lists

wiki show
your wiki: its Knowledge Base, its boards, page count and the folders it is synced to
wiki set [--shortcut K] [--hotkey 0-9|none] [--recordings-folder PATH]
the folder on your Google Drive its meeting recordings are in ("" clears it); a page whose front matter says recording: gdrive:<path> plays it beside its transcript
drive status
your Google Drive connection, and your wiki's recordings folder
wiki locate <path>
which board a path in your wiki lands in, and the rest
wiki resolve <link...>
the page a [[link]] finds anywhere in your wiki (Note, or Folder/Note; the shortest path wins)
wiki wanted
pages linked to but never written, every board at once
wiki tree [--short-names]
every folder and file by name
wiki changes [--since N] [--limit N] [--short-names]
what changed (pages, folders, attachments) after cursor N, each once and as it is now; without --since, the cursor to start from. What sync polls
wiki import <dir> [--dry-run] [--all]
bring an existing Obsidian vault in, once: each note a page and each other file a file at its path in your wiki, in the board whose folder holds it, bytes as they are (front matter, Excalidraw, Meld ciphertext). What the server has at a path already is left alone. --dry-run says what would be created or skipped, and which links, embeds and plugin blocks won't resolve. Afterwards, `sync init` on the same folder adopts the files instead of duplicating them

Sync

(your wiki mirrored both ways to a local folder that stays a valid Obsidian vault. The server is the source of truth; the folder is a working copy, and anything that writes a file into it writes into your wiki)

sync init <dir>
bind a folder to your wiki, then run once. Files already there that match your wiki are adopted, not duplicated
sync [<dir>]
one pass, both ways (default: the folder you are in). A .md file is a page; images, PDFs, .excalidraw and other files are kept at the same path (250 MB each), so ![[image.png]] works on both sides. A rename or move is the same page; a delete archives it. Changed on both sides: the server's version keeps the path and yours is saved beside it as "Name (conflict DATE host).md", and synced too. Dot folders (.obsidian, .trash) and editors' temp files are left alone, and so is anything named in .slipdockignore (gitignore-style: *.pdf, Private/)
--watch       keep running: a pass once the folder has been still for 2 s, and
