Working with an AI agent

Claude, ChatGPT, Codex, Cursor, or a script you wrote can all read and work these boards. The agent runs wherever you already use it (your laptop, a cloud session, a phone app) and talks to this server over the web, as your browser does. It never runs on the server, and you don't need access to the machine the server runs on.

There are several ways to connect, depending on where the agent runs and who starts the work. Most people need only one or two. Each one is introduced briefly below, followed by a table comparing them; every way has its own page with more detail.

The ways in

The agent guide & HTTP API

Paste one prompt that points the agent at this server's guide. The guide explains the boards and gives a curl line for every call, so any agent that can run a shell command can start straight away.

Use it when you want the quickest start, or the agent can make HTTP requests but you can't or won't install anything.

More about Guide & API →

MCP server

This server is also an MCP server. Add it as a connector and the agent gets tools to read and write boards, cards and wiki pages, with no shell needed.

Use it when you use claude.ai, the Claude desktop or mobile apps, ChatGPT, or any other client that speaks MCP. It's also a tidy option for Claude Code.

More about MCP →

The slipdock CLI

A command-line client that wraps the whole API. It keeps the token for you, reads better in a transcript than raw curl, and does a few things nothing else does.

Use it when the agent works in a terminal on your machine, or you want what only the CLI has: syncing your wiki to a folder, files over 10 MB, imports and exports.

More about CLI → Every CLI command →

Skills

Longer instructions installed where the agent looks for them. They cover judgement more than syntax: what to pick up next, what belongs on the wiki, and how to work a backlog unattended.

Use it when you'll work with an agent here regularly and want it to follow the board's conventions without being told. Use them alongside the CLI or MCP.

More about Skills →

Runners

Reverses the direction: the board sends cards to an agent on a machine of yours when something happens, such as a card arriving in a list. The agent works the card and reports back.

Use it when you want work to start without anyone opening a session, such as a list that agents empty on their own, or a queue several machines share.

More about Runners →

Webhooks

An automation can call a URL of yours when something happens on a board. The request carries the card's details, so your own service can react to it.

Use it when you have your own service or workflow tool (n8n, Zapier, an agent behind an HTTP endpoint) and it only needs to know when something happened.

If you're not sure

  • Using claude.ai, ChatGPT or a phone? Add the MCP connector .
  • Claude Code, Codex or another terminal agent? Start with the guide , then add the skills and either MCP or the CLI once you use it often.
  • Want cards worked without you there? Connect a runner .
  • Only need to tell another system something happened? Use a webhook .
