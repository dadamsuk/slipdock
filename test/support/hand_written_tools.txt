# line here whose tool is now made from a definition or is gone. The list

# only when it combines several operations. One tool name per line.

# Not one definition (#3187): MCP's list_cards answers lines, a page of
# them (limit, truncated, total) with done lists left out unless asked,
# or each card as get_card has it (full); REST's GET /api/boards/:board/
# cards answers every card in full and is what the CLI's `cards` reads.
# One result shape would cost MCP's callers their context or REST's
# callers their answer: Ops 5 (#3190) takes its params from a definition.
list_cards

# Not one definition (#3188): REST's GET /api/search answers each result
# with every match's whole text (a chunk is up to 1,500 characters), the
# board and list as objects and relative links, 20 by default and up to
# 50, and is what the CLI's `search --full` prints; MCP's answers each
# result's best match cut to 300 characters with absolute links, 10 by
# default and up to 30. The same reason as list_cards: one shape would
# cost MCP's callers their context or REST's callers their answer.
search

# Not one definition (#3188): REST's GET /api/guide needs no token,
# answers Markdown (JSON only when asked) and, without a section, the
# whole guide, as the URL quoted in prompts and docs has always served;
# MCP's get_guide answers JSON, the short guide by default (the whole one
# is more than a tool result shows), and with board that board's skills,
# which REST serves at GET /api/boards/:board/skills. Each default is on
# purpose, so neither can take the other's.
get_guide
