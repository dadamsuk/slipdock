# The tests that hold the repository's own files, docs and skills to a rule
# or to the server (#1867). `mix pre_push` runs them, because a builder runs
# only the tests it added or changed and the pull request's CI the rest, and
# these are the ones a change elsewhere breaks. They run in about 15 s.
#
# What qualifies (W-1950 §Tests):
# - source conventions: a rule read off lib/ (fonts, buttons, controls,
#   design tokens, date inputs and the like);
# - the boundaries read off the compiler's cross-reference graph (`mix xref
#   graph`): a context calling SlipdockWeb, compile-connected cycles (#1963);
# - docs and skills held to the server: docs/, README.md and priv/skills/
#   against the guide, the tools, the CLI or each other;
# - fixture uniqueness, and nothing personal.
# A feature test that also holds a doc or a skill to what it built goes on
# too, as a whole file, as long as it is cheap: the list's budget is 20 s.
# One that is too slow for that, or whose docs/ or lib/ paths are only data,
# is an exception below, with its reason.
#
# `test/slipdock/repo_checks_test.exs` fails when a test file reads docs/ or
# priv/skills/, wildcards over lib/ or test/, or reads `mix xref`, and is
# neither listed here nor an `except <path>: <reason>` line.
